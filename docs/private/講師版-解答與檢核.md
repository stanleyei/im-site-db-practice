# 看畫面設計資料庫：資管系網站練習（講師版）

本檔與同目錄的 `site-data.js`、`seed.sql` 不進版控（`.gitignore` 排除 `docs/private/`），請勿發給學生。
畫面內容、種子資料、本檔解答都由 `site-data.js` 產生，改資料後執行 `npm run build` 會同步更新 `index.html` 與 `seed.sql`，本檔的預期結果則需手動核對。

練習情境的「今天」為 **2026-09-16**。解答中的 `CURDATE()` / `NOW()` 若在其他日期示範，請改成 `'2026-09-16'` 字面值。

## 參考設計（18 張表、86 筆）

這是**一種可接受的設計**，不是唯一解。學生的表名欄名不同不扣分，重點是下面「檢核點」有沒有做對。

```
news_categories (id, name, sort_order)
news (id, category_id→news_categories, title, content, is_top, published_at, expired_at NULL, view_count)
news_attachments (id, news_id→news, file_name, file_size_kb)
tags (id, name)
news_tags (news_id→news, tag_id→tags)                    ← 全站唯一的多對多

download_categories (id, name)
downloads (id, category_id→download_categories, title, file_name, file_size_kb, download_count, updated_at DATE)

events (id, title, location, start_at, end_at, registration_deadline DATE NULL, description)

staff_titles (id, name, sort_order)
staff (id, name, title_id→staff_titles, position NULL, office, extension NULL, email, expertise, sort_order)

albums (id, title, description, shot_date)
photos (id, album_id→albums, file_name, caption, is_cover)

faq_categories (id, name, sort_order)
faqs (id, category_id→faq_categories, question, answer, sort_order, is_visible)

link_categories (id, name)
links (id, category_id→link_categories, name, url, open_new_window, sort_order)

message_statuses (id, name, sort_order)                  ← 未處理／處理中／已回覆
contact_messages (id, name, email, subject, content, status_id→message_statuses, created_at, replied_at NULL)
```

完整 DDL 與 INSERT 見 `seed.sql`，可直接在 HeidiSQL 執行來示範或給進度落後的學生匯入。DDL 中有外鍵，若課程階段不強調約束可整段刪除，不影響任何題目。

可接受的變形：

- 檔案格式（PDF／DOCX）從檔名推導或另存欄位皆可。
- `is_cover` 改為 `albums.cover_photo_id` 也可以，但要能回答 C4。
- 留言狀態直接存成文字欄位（VARCHAR）也可以，但要能回答 D4；本練習刻意不用 ENUM，以保持「固定幾種值就拆查找表」的一致原則。
- 教師「行政職」做成獨立表也可以。

## 檢核點對照

| 題號 | 檢核的設計決策 | 設計錯誤時的症狀 |
|---|---|---|
| A1、A2、D1 | `published_at`、`expired_at` 為 DATETIME；`is_top` 為布林 | 日期存文字時排序錯；「上架中」若被做成靜態欄位，下架後不會自動變 |
| A3 | 基本 LIKE | — |
| A4、D3 | 活動的起訖是兩個 DATETIME 欄位，「已結束」是算出來的 | 存「09:00–12:00」文字者無法比較 |
| A5、B3、C2 | 檔案大小以整數 KB 儲存 | 存「1.3 MB」文字者無法排序與加總；C2 的換算需要 `ROUND(kb/1024,1)` |
| B1 | 分類拆表 + LEFT JOIN | 分類為文字欄位者永遠列不出「學術演講 0」 |
| B2、C5、C6 | 標籤為多對多中介表 | 逗號字串者 B2 做不出、C5 要用兩個 LIKE、C6 要判空字串 |
| B4、B5 | GROUP BY 與聚合 | — |
| C1 | 附件為獨立表（1:N） | 附件做成公告表的多個欄位者無法 COUNT |
| C3 | 職稱查找表 + `sort_order` | 職稱手打者會出現「副教授」「副 教授」分裂 |
| C4 | 相簿與照片 1:N、封面旗標 | 沒有封面欄位者答不出第二問 |
| C7 | `open_new_window` 布林 + `sort_order` | 用「↗」符號存進名稱者是錯的 |
| D2、D5 | DATETIME 相減：`TIMESTAMPDIFF` | 存文字者無法計算 |
| D4 | 狀態拆成三筆查找表（未處理／處理中／已回覆）且 `replied_at` 可為 NULL | 只用 `replied_at IS NULL` 判斷也對，但若學生沒存狀態欄位，「處理中」這個資訊就丟了，可藉此討論 |
| D6 | `is_visible` 旗標與雙層排序 | 直接刪掉隱藏問答者會在 E3 露餡 |
| E1 | 主鍵取得後再插入子表（`LAST_INSERT_ID()`） | 附件塞在公告表者只能插兩個欄位 |
| E2 | UPDATE 兩個欄位，狀態值需先從查找表取得 id | 狀態存文字者直接寫字串即可，可討論兩者差異 |
| E3 | 邏輯刪除 vs 實體刪除的討論 | — |
| E4 | 先刪子表再刪父表 | 有外鍵時反過來會被擋、沒有外鍵時反過來會留下孤兒照片 |

## 參考解答與預期結果

以下以參考 schema 撰寫，`im_site` 資料庫。

### A. 基礎查詢

**A1**
```sql
SELECT title, published_at
FROM news
WHERE expired_at IS NULL OR expired_at >= '2026-09-16'
ORDER BY published_at DESC;
```
7 筆：8, 7, 6, 4, 3, 2, 1（5 號已下架不出現）。

**A2**
```sql
SELECT title, is_top, published_at
FROM news
WHERE expired_at IS NULL OR expired_at >= '2026-09-16'
ORDER BY is_top DESC, published_at DESC
LIMIT 5;
```
順序：2（碩士班說明會）、1（選課注意事項）、8、7、6。

**A3**
```sql
SELECT title FROM news WHERE title LIKE '%招生%';
```
2 筆：碩士班甄試招生說明會、轉學考招生簡章公告。

**A4**
```sql
SELECT title FROM events WHERE end_at < '2026-09-16';
```
1 筆：新生始業式。

**A5**
```sql
SELECT title, file_name, file_size_kb
FROM downloads
WHERE file_name LIKE '%.pdf'
ORDER BY file_size_kb DESC;
```
5 筆：課程地圖 3072、HeidiSQL 說明 1843、課程大綱 256、同意書 120、離校程序單 96。

### B. 彙總統計

**B1**
```sql
SELECT c.name, COUNT(n.id) AS news_count
FROM news_categories c
LEFT JOIN news n ON n.category_id = c.id
GROUP BY c.id, c.name
ORDER BY c.sort_order;
```
系所公告 2、招生資訊 2、競賽活動 2、就業實習 2、學術演講 0。

**B2**
```sql
SELECT t.name, COUNT(nt.news_id) AS used
FROM tags t
LEFT JOIN news_tags nt ON nt.tag_id = t.id
GROUP BY t.id, t.name;
```
招生 2、競賽 2、獎學金 1、講座 0、實習 2。

**B3**
```sql
SELECT SUM(file_size_kb) AS total_kb FROM downloads;                 -- 5435
SELECT title FROM downloads ORDER BY file_size_kb DESC LIMIT 1;      -- 115 學年度課程地圖
```

**B4**
```sql
SELECT c.name, SUM(d.download_count) AS total_downloads
FROM download_categories c
JOIN downloads d ON d.category_id = c.id
GROUP BY c.id, c.name;
```
表單下載 2639、課程資料 3188、軟體資源 1502。

**B5**
```sql
SELECT SUM(view_count), AVG(view_count) FROM news;
```
總和 3948、平均 493.5。

### C. 關聯查詢

**C1**
```sql
SELECT n.title, COUNT(a.id) AS attachment_count
FROM news n
JOIN news_attachments a ON a.news_id = n.id
GROUP BY n.id, n.title
HAVING COUNT(a.id) > 1;
```
2 筆：選課注意事項 2、轉學考招生簡章公告 2。

**C2**
```sql
SELECT a.file_name, ROUND(a.file_size_kb / 1024, 1) AS size_mb
FROM news_attachments a
JOIN news n ON n.id = a.news_id
WHERE n.title LIKE '%轉學考招生簡章%';
```
轉學考招生簡章.pdf 1.3、轉學考報名表.docx 0.1。畫面上小檔顯示「64 KB」，可討論顯示層與儲存層的差異。

**C3**
```sql
SELECT s.name, t.name AS title, s.office
FROM staff s
JOIN staff_titles t ON t.id = s.title_id
ORDER BY s.sort_order;
```
王志明 教授 IB512 … 黃雅婷 講師 IB522，共 6 筆。

**C4**
```sql
SELECT al.title,
       COUNT(p.id) AS photo_count,
       MAX(CASE WHEN p.is_cover = 1 THEN p.file_name END) AS cover_file
FROM albums al
LEFT JOIN photos p ON p.album_id = al.id
GROUP BY al.id, al.title;
```
成果展 3 張、封面 album-expo-1.webp；系友回娘家 3 張、封面 album-alumni-2.webp。

**C5**
```sql
SELECT n.title
FROM news n
JOIN news_tags nt ON nt.news_id = n.id
JOIN tags t ON t.id = nt.tag_id
WHERE t.name IN ('競賽', '獎學金')
GROUP BY n.id, n.title
HAVING COUNT(DISTINCT t.id) = 2;
```
1 筆：2026 全國大專校院資訊應用服務創新競賽 徵件開始。

**C6**
```sql
SELECT n.title
FROM news n
LEFT JOIN news_tags nt ON nt.news_id = n.id
WHERE nt.news_id IS NULL;
```
2 筆：選課注意事項（1 號）、電梯保養公告（5 號）。

**C7**
```sql
SELECT l.name, l.url, l.open_new_window
FROM links l
JOIN link_categories c ON c.id = l.category_id
WHERE c.name = '相關資源'
ORDER BY l.sort_order;
```
MariaDB 官方文件、drawSQL、HeidiSQL，三者皆另開視窗。

### D. 進階查詢

**D1**
```sql
SELECT title
FROM news
WHERE published_at <= '2026-09-16 23:59:59'
  AND (expired_at IS NULL OR expired_at >= '2026-09-16 00:00:00');
```
7 筆，與 A1 相同集合。

**D2**
```sql
SELECT title, start_at, end_at,
       TIMESTAMPDIFF(HOUR, start_at, end_at) AS hours
FROM events
WHERE start_at >= '2026-09-01' AND start_at < '2026-10-01';
```
新生始業式 3 小時、碩士班甄試招生說明會 2 小時。

**D3**
```sql
SELECT title, registration_deadline
FROM events
WHERE start_at > '2026-09-16' AND registration_deadline IS NOT NULL;
```
碩士班甄試招生說明會 09-22、業界講座 09-29、系友回娘家餐會 11-06。

**D4**
```sql
SELECT m.id, m.name, m.subject, s.name AS status, m.created_at
FROM contact_messages m
JOIN message_statuses s ON s.id = m.status_id
WHERE s.name <> '已回覆'
ORDER BY m.created_at;
```
3 劉先生（未處理）、4 林同學（處理中）、5 匿名（未處理）。
用 `replied_at IS NULL` 也會得到同樣三筆，可順帶討論兩種寫法在「處理中」語意上的差異。

**D5**
```sql
SELECT id, name,
       ROUND(TIMESTAMPDIFF(MINUTE, created_at, replied_at) / 60, 1) AS hours
FROM contact_messages
WHERE replied_at IS NOT NULL;
```
1 吳同學 23.3 小時、2 陳家長 1.4 小時。

**D6**
```sql
SELECT c.name AS category, f.question
FROM faqs f
JOIN faq_categories c ON c.id = f.category_id
WHERE f.is_visible = 1
ORDER BY c.sort_order, f.sort_order;
```
4 筆（3 號隱藏不出現）。

### E. 異動操作

**E1**
```sql
INSERT INTO news (category_id, title, content, is_top, published_at, expired_at, view_count)
VALUES ((SELECT id FROM news_categories WHERE name = '就業實習'),
        '115 學年度校外實習說明會', '（內文）', 0, '2026-09-16 10:00:00', NULL, 0);

SET @news_id = LAST_INSERT_ID();

INSERT INTO news_attachments (news_id, file_name, file_size_kb) VALUES
  (@news_id, '實習說明會簡報.pdf', 2300),
  (@news_id, '實習合作企業名單.xlsx', 45);
```
之後 B1 的就業實習變 3，C1 多一筆。

**E2**
```sql
UPDATE contact_messages
SET status_id = (SELECT id FROM message_statuses WHERE name = '已回覆'),
    replied_at = '2026-09-16 09:15:00'
WHERE id = 4;
```

**E3**
```sql
DELETE FROM faqs WHERE id = 3;
```
D6 結果不變。可延伸討論：既然有 `is_visible`，實務上通常不真的刪除。

**E4**
```sql
DELETE FROM photos WHERE album_id = (SELECT id FROM albums WHERE title = '2025 系友回娘家');
DELETE FROM albums WHERE title = '2025 系友回娘家';
```
先刪照片再刪相簿。有外鍵時順序顛倒會報錯；沒外鍵時顛倒不會報錯，但會留下指向不存在相簿的照片，這正是「即使沒建約束，邏輯上仍要當它存在」的教學點。

## 課堂進行建議

| 時段 | 內容 |
|---|---|
| 0:00–0:20 | 全班一起瀏覽網站，只做「這個畫面有哪些東西要存」的口頭盤點，不給答案 |
| 0:20–1:20 | 個人或兩人一組在 drawSQL 畫 ERD |
| 1:20–1:40 | 抽幾組投影 ERD，針對「分類要不要拆表」「附件放哪裡」「大小存什麼型別」討論，但不公布參考設計 |
| 1:40–3:00 | HeidiSQL 建表、輸入資料 |
| 3:00–4:30 | 查詢題 A 到 D，鼓勵卡關時回頭改設計（改設計代表學到東西，不是失敗） |
| 4:30–5:00 | E 段異動題與 E4 的順序討論 |
| 收尾 | 公布參考設計與 `seed.sql`，請學生對照自評表 |

常見的錯誤設計與引導語：

- **分類直接打字**：「如果系辦說『招生資訊』要改名叫『招生訊息』，你要改幾筆？」
- **附件做成欄位**：「第三個附件要放哪？」
- **大小存文字**：「請算出所有附件總共佔多少空間。」
- **日期存文字**：「請把 9 月 5 日和 8 月 25 日排序，資料庫怎麼知道誰先？」
- **標籤用逗號**：「請找出同時有競賽和獎學金的公告。」
- **把「已結束」「上架中」存成欄位**：「明天誰來把它改成已結束？」
